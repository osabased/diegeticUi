# M010 — World container lifecycle and server access

- Completed: 2026-09-23
- Result: A server lifecycle root creates a visible supply crate and binds it to one session inventory with a generated lookup ID. Inspection and claims require a live, present player near the still-present part; claim eligibility is checked again after readiness and in the commit path. Expiration closes access immediately and defers inventory disposal until in-flight claims finish. [ADR 0003](../../docs/adr/0003-world-container-access.md) records the scoped snapshot delivery contract for the next protocol move.

A live Studio session spawned the crate with a generated ID and no startup errors; a temporary probe in Studio's separate server command environment accepted a nearby inspection, rejected a distant one, and rejected access after expiration. The command environment had a separate module cache, so it could not inspect the live lifecycle root's private registration. Studio API access was disabled, so this did not verify durable DataStore saves.
