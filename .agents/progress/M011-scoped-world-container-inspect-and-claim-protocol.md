# M011 — Scoped world-container inspect and claim protocol

- Completed: 2026-09-23
- Result: Blink now carries a bounded item-list response for eligible world inspection and a revisioned claim request. The server maps only its validated container snapshot to the requesting player and derives claim identity from Blink's sender. The client validates and detaches the inspected snapshot, receives both claim revisions or stable rejection feedback, and continues to receive player inventory through Scribe. Inspection is request-scoped; view dismissal and refresh after access loss belong to the next presentation move.
- Verification: The canonical verifier passed with 32 native tests, lint, analysis, Blink codegen integrity, and build profiles. The guarded Studio suite passed 37 tests after one run caught the previously observed intermittent late callback diagnostic despite all assertions passing. In a connected Studio session, an eligible client inspected two items, claimed them at revisions 0→1→2, received `StaleRevision` and `NotEligible` without consuming the remaining item, then received `ContainerMissing` for inspect and claim after part removal. The task-owned session was stopped. Studio API access was disabled, so this does not establish durable DataStore saves or a rendered loot view.
